# 自动更新链路风险说明

> 生成日期：2026-09-28，随 v3.6.13 → v3.7.2 同步一并整理。
> **状态：已处置（2026-09-28）—— 两条链路均改为「只检测、不拉取」。**
> 详见下方第七节。

---

## 一、问题是什么

本分支（全员性转版）里有 **两处**会自动从**上游仓库** `vincentrong2005/Fatria` 拉取内容。
一旦触发，拉下来的是**原版（未性转）**内容，会把你辛苦改的性转成果覆盖掉。

简单说：**这两个功能原本是「把你自己的分支换回原版」的开关。**

---

## 二、链路一：脚本一键更新

**位置**：[src/性斗学园/性斗学园脚本/scriptUpdater.ts](../性斗学园脚本/scriptUpdater.ts)

关键代码：

```text
第 7 行   const JSDELIVR_REPOSITORY_PATH = '/gh/vincentrong2005/Fatria';
第 15 行  const UPDATE_MANIFEST_URL = 'https://raw.githubusercontent.com/vincentrong2005/Fatria/...'
第 9 行   const SCRIPT_BUNDLE_PATH = '/dist/性斗学园/性斗学园脚本/index.js';
```

**行为**：用户点「一键更新」时，脚本会

1. 从上游的 `update-manifest.json` 读取最新版本号
2. 从 jsDelivr 按发布标签下载上游的 `index.js` 产物
3. **改写脚本 URL**，指向刚下载的上游版本

**影响**：整个脚本包被替换成原版 → 所有性转改动（角色名、台词、映射表）全部丢失。

**当前触发条件**：`SCRIPT_VERSION` 本次已同步为 `3.7.2`，与上游一致，
所以**现在不会触发**。但**上游一旦发布 v3.7.3，它就会提示并可执行更新——那时就会覆盖。**

## 三、链路二：世界书脚本自动更新角色卡

**位置**：[src/性斗学园/自动更新世界书脚本/index.ts](../自动更新世界书脚本/index.ts)

关键代码：

```text
第 4 行   const CHARACTER_NAME = '性斗学园超级重制版';
第 7 行   const GITHUB_BASE_URL = 'https://raw.githack.com/vincentrong2005/Fatria/main/src/性斗学园';
第 25-28 行  await importRawCharacter(CHARACTER_NAME, await fetch(`${GITHUB_BASE_URL}/性斗学园超级重制版.png`)...)
```

**行为**：

1. 读本地世界书的「版本号」条目
2. 从上游拉 `版本号.txt` 比对
3. 只要上游版本更高，就**直接 `importRawCharacter` 覆盖角色卡**

**影响**：角色卡本体被换成上游原版。

**这条比链路一更危险**，因为：

- 它在脚本加载时**自动执行**（文件末尾直接 `checkUpdate();`），不需要你点任何按钮
- 它是**静默**的——成功了只弹一个 toastr「角色卡自动更新成功」

## 四、可选处置方向

三条路，各有取舍。**都需要你单独授权我才动**。

### 方案 1：改指向你自己的仓库

把两处的 `vincentrong2005/Fatria` 换成本分支的仓库地址。

- **好处**：自动更新从「威胁」变成「功能」——以后自动更新的是你自己的性转版
- **前提**：你得先把产物发布到自己的仓库，并维护对应的 `版本号.txt` / `update-manifest.json` / 打包好的 `.png`
- **代价**：需要搭一套发布流程

### 方案 2：关掉自动检查

保留手动更新入口，去掉启动时的自动拉取（主要是链路二的 `checkUpdate();`）。

- **好处**：改动最小，立刻消除静默覆盖的风险
- **代价**：失去自动更新便利性；链路一的「一键更新」按钮仍在，误触仍会覆盖

### 方案 3：维持现状

- **好处**：不动任何代码
- **代价**：每次上游发新版，链路二都可能静默覆盖角色卡；链路一误触也会覆盖
- **必须做的**：确保本分支有可回退的版本（Git 提交 / 备份），以便覆盖后能恢复

## 五、我的建议

如果暂时不想动代码，**至少要做一件事**：把当前性转版**提交到 Git**（或完整备份一份）。

理由：链路二是静默自动执行的，「哪天角色卡突然变回原版」这种事很难第一时间联想到是它，
有一个可回退的基线会省很多事。

> 注意：提交与推送属于你单独授权的事项，本次同步**没有**执行。
