# 角色名映射总表（男性显示名 ⇄ 女性资源名）

> 本文档汇总《性斗学园》中**全部**男名／女名的对应关系，供改名、新增角色、排查资源路径时查阅。
> 内容由 `src/性斗学园` 当前代码中的映射表汇总生成。

---

## 一、命名约定

| 场景 | 使用名字 |
| --- | --- |
| 界面显示、战斗日志、对话、变量键与变量值、角色昵称 | **男性名** |
| CDN 资源路径（立绘／头像／Q版头像／头像差分／CG 图片） | **女性名** |

也就是说：**女性名只出现在 URL 与少数旧键名中**，前者见下面各张映射表的「资源名」一侧，后者见第七节。

**默认规则：凡未出现在本文档中的名字，男女两名一致**，无需任何映射。
例如新角色 `庄方宜`、`日向葵`，以及 `阿娜温`、`无常`、`零`、`雪` 等均属此类。

## 七、昵称兼容（`NAME_ALIASES`）

`NAME_ALIASES` 的作用是：**把角色昵称、简称、称号映射回男性名全名**，供旧存档与模糊输入识别。
绝大多数条目左右两侧都是男性名：

| 昵称／简称 | 解析为（男性名全名） |
| --- | --- |
| 白川 | 白川千秋 |
| 色欲 | 维斯佩罗 |
| 龙君 | 庄方宜 |
| 书记 | 克里斯_1 |
| 西园寺辉夜 | 山田花男 |
| …… | 其余两百余条同理 |

### 女名 → 男名的桥接条目

另有两条**左侧是女性资源名**的条目，它们不是残留，而是有意保留的桥接：

| 左（女性资源名） | 右（男性名全名） |
| --- | --- |
| 薇丝佩菈 | 维斯佩罗 |
| 黑崎晴雯 | 黑崎晴雷 |

之所以需要它们：`开局/npcCharacters.ts` 的 `黑崎晴雯`／`薇丝佩菈` 条目中，
`dbKey`／`skillKey` 仍直接使用**女性资源名**（而未改成男名全名），
且 `开局/app.vue` 会用这两个键**裸查** `ENEMY_DATABASE` 与 `ENEMY_SKILL_MAP`。

而这两张表都只认**男名**作为键（`ENEMY_DATABASE[黑崎晴雷]`、`ENEMY_SKILL_MAP[维斯佩罗]`、`ENEMY_SKILL_MAP[黑崎晴雷]`），
并无女名键。因此必须在 `NAME_ALIASES` 中保留这两条「女名 → 男名」桥接，
让女名能先解析到男名数据上，否则开局这两个角色会读不到技能与属性。

> 规则可以概括为：**女名只用于"取资源"和"作旧键"**，凡是面向玩家的文字一律用男名。
> 因此 `NAME_ALIASES` 左侧出现女名是允许的，只要右侧指向男名全名即可。

## 九、维护提示

1. 新增角色时，若资源文件名与显示名相同，**什么都不用配**；不同才在对应的资源映射表补一条。
2. 角色改名时，在 `NAME_ALIASES` 补「旧名 → 新名」，否则旧存档会失去识别。
3. 女性资源名**不要**出现在日志、UI 文案、变量键、`buffName`／`statusName` 中，这些位置一律用男名。
   唯一的例外是 `开局/npcCharacters.ts` 中仍沿用女名的 `dbKey`／`skillKey`，
   且必须在 `NAME_ALIASES` 中有一条「女名 → 男名」的桥接。
4. 本表由代码映射表汇总生成，改动映射后请重新核对第三、四节的条目数。
