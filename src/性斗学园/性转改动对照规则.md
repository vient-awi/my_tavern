# 性转改动对照规则

> 用途：每次同步上游 [vincentrong2005/Fatria](https://github.com/vincentrong2005/Fatria) 更新时，
> 用这份文档判断「哪些地方必须翻译、哪些可以直接照搬」，避免性转成果被上游冲掉。
>
> 本文档由 2026-09-28 的 v3.6.13 → v3.7.2 同步实践整理而成。

---

## 一、命名约定（一切规则的出发点）

| 场景 | 用哪个名字 |
| --- | --- |
| 界面显示、战斗日志、对话台词、变量键与变量值、角色昵称 | **男名** |
| CDN 资源路径（立绘／头像／Q版头像／头像差分／CG 图片文件名） | **女名** |

一句话记法：**玩家看得到的用男名，URL 里的用女名。**

**默认规则：没出现在映射表里的名字，男女两名一致**，不需要任何处理。
例如 `庄方宜`、`日向葵`、`阿娜温`、`无常`、`零`、`雪` 都属这类。

## 二、五张映射表（性转成果的核心，改上游前必查）

| 映射表 | 文件 | 条目数 | 作用 |
| --- | --- | --- | --- |
| `PORTRAIT_NAME_MAP` | [战斗界面/constants.ts](src/性斗学园/战斗界面/constants.ts) | 138 | 男名 → 立绘 CDN 女名 |
| `CHIBI_RESOURCE_NAME_MAP` | [性斗学园脚本/phone/backstreetAvatarSettings.ts](src/性斗学园/性斗学园脚本/phone/backstreetAvatarSettings.ts) | 126 | 男名 → Q版头像 CDN 女名 |
| `resourceName` 字段 | [战斗界面/data/cgConfig.ts](src/性斗学园/战斗界面/data/cgConfig.ts) | 22 处 | CG 图片的资源名 |
| `imageFolder` 字段 | [shared/avatarVariationStore.ts](src/性斗学园/shared/avatarVariationStore.ts) | 129 处 | 头像差分的文件夹名 |
| `NAME_ALIASES` | [战斗界面/enemyDatabase.ts](src/性斗学园/战斗界面/enemyDatabase.ts) | 230 | 昵称／简称 → 全名 |

**判定某条目是否属于性转改动的方法：** 看它在表里的值。
凡是「键是男名、值是女名」的条目，就是性转产物，**上游改动不能直接覆盖**。
键和值相同的自映射条目**也是有意为之**——它们用于挡住精确别名匹配那一步的前缀误伤
（例如 `雪: '雪'` 能防止「雪男」被解析到「雪」）。**不要因为「看起来冗余」就删掉。**

## 三、文案改写约定

上游新增或修改的**用户可见文本**，需要按下列约定翻译；代码注释和 `console` 日志可以不动。

### 3.1 人名

直接查上面五张表，用男名。

### 3.2 性别用词对照

| 上游（女） | 本分支（男） |
| --- | --- |
| 她／她们 | 他／他们 |
| 少女、女孩、女子 | 少男、男孩、男子 |
| 小姐、女士、夫人 | 少爷、男士、先生 |
| 姐妹 | 哥弟 |
| 娘（狼娘、猫娘…） | 郎（狼郎、猫郎…） |
| 女王、公主、女武神 | 男王、王子、男武神 |
| 母（万魔之母） | 父（万魔之父） |
| 女吊 | 男吊 |

### 3.3 必须用男名的位置（漏改会出 bug，不只是观感问题）

- **`buffName` / `statusName`** —— 这些是变量键，会参与状态匹配
- **对话日志的 template string** —— 例如 `【束缚猎物】${name}的攻击必定命中`
- **UI 文案与结算提示**
- **变量键与变量值**

### 3.4 ⚠️ 最容易漏的一类：**用正则/字符串匹配名字的判定代码**

这是 2026-09-29 排查时发现的**系统性漏改模式**，每次同步上游都要专门查一遍。

**问题形态**：技能名、性格名这些**被匹配的字符串**改成了男名，
但**负责匹配它们的正则或判断**没跟着改，于是那段判定**静默失效**——
不报错、不崩溃，只是行为悄悄退回默认值。

已发现并修复的实例：

| 文件 | 原（女） | 应改为（男） | 不修的后果 |
| --- | --- | --- | --- |
| `exorcismEnemySkills.ts` `inferHitCount()` | `/姐妹/` | `/兄弟/` | 「兄弟的誓约」等技能少算一段攻击 |
| 同上 `inferTags()` | `/圣母/` `/母\|母性\|子宫/` | `/圣父/` `/父\|父性\|生殖腔/` | 这些技能打不上 holy / mother 标签，技能分类错乱 |
| 同上 `inferType()` | `/母性/` | `/父性/` | 类型判定落到 PHYSICAL 兜底，不是 CHARM |
| 同上 `inferIcon()` | `/母/` | `/父/` | 图标退回默认 |
| 同上 `inferBuffs()` | `/母性改造/` | `/父性改造/` | 该加的攻击 buff 不加 |
| `virtueItems.ts` `bossAliases` | `'鼠族公主'` | `'鼠族王子'` | 别名匹配不上 `ENEMY_DATABASE` 的键，美德装备掉落判定失效 |

**排查方法**：搜出所有「拿名字去做判断」的地方，逐个核对正则里的关键词是否也是男名。

```bash
grep -rn "\.test(\|includes(\|startsWith(\|indexOf(\|match(" src/性斗学园 --include=*.ts --include=*.vue \
  | grep -E "姐|妹|母|女|娘|妻|嫂|婆|妇|她"
```

结果要**逐条判断**，因为有些是正常的：

- `=== '女'` 这类是**性别值比较**（存档里 `性别` 字段的真实取值），**不该改**
- 映射表的「值」列（CDN 女名）、`八尺夫人` 这类桥接**别名键**，**是故意保留的**

### 3.5 ⚠️ 第二类：**玩家性别判断——要分「资源侧」和「判断侧」，别一刀切**

**最容易帮倒忙的一类。** 代码里判断**玩家性别**的字面量看着像「没改干净的女字旁」，
但改不改**要看它决定的是哪种东西**，两类结论正好相反：

#### (a) 决定「给玩家看哪份资源」→ 要反

上游给「男玩家」用的立绘／CG 目录，在本分支是给「女玩家」的。
判断条件跟着反，才能让同一个玩家拿到同一份资源。

| 位置 | 本分支的值 | 说明 |
| --- | --- | --- |
| [phone/backstreetAvatarSettings.ts](性斗学园脚本/phone/backstreetAvatarSettings.ts) `getDefaultPlayerAvatarUrl()` | `=== '女' ? '男主'` | 上游是 `'男'`。**本分支这个 `'女'` 是对的**，改回 `'男'` 会让男女默认头像对调 |
| [data/cgConfig.ts:4071](战斗界面/data/cgConfig.ts#L4071)、[CGPage.vue:419](性斗学园脚本/components/pages/CGPage.vue#L419) | `playerGender === '男' ? '男u' : '女u'` | **和上游一致，不要动**。CDN 上的 `男u`／`女u` 目录本身**没有对调**（属于"URL 里的资源名"，按第一节约定保持原样），判断也就该保持上游写法 |

#### (b) 决定「读哪一份上游就写好的数据表」→ 不要反

**这类是本轮踩的坑，单独记下来。**

[战斗界面/app.vue](战斗界面/app.vue) 的敌人技能变体选择（艾格纳斯／弗林／维斯佩罗）读的是
`ENEMY_SKILL_MAP` 里的 `艾格纳斯_男`。这个键**是上游写的，内容也是上游写的**，
本分支只是照搬，没有任何对调。

判据在键的内容里，看技能池针对谁：

| 键 | 池内的技能 | 注释 | 实际含义 |
| --- | --- | --- | --- |
| `艾格纳斯_男` | `艾格纳斯_女性_N` | `// 针对女性玩家的技能池` | **给男玩家准备的** |
| 上游 `芙莲_男` | `芙莲_男性_N` | `// 针对男性玩家的技能池（去雄系技能，数值更高）` | **给男玩家准备的** |

所以 `_男` = "给男玩家的"，判断就该是 `playerGender === '男' ? '艾格纳斯_男' : '艾格纳斯'`。

| 位置 | 本分支的值 |
| --- | --- |
| [战斗界面/app.vue:2231-2240](战斗界面/app.vue#L2231) 敌人变体选择（艾格纳斯／弗林／维斯佩罗） | `playerGender === '男' ? '艾格纳斯_男' : '艾格纳斯'` |
| [战斗界面/bossSystem.ts:2447](战斗界面/bossSystem.ts#L2447) 艾格纳斯开场白 | `playerGender === '女'` —— 与上游一致，**未改动** |

**结论**：遇到玩家性别判断**先停下来问一句——它决定的是"给玩家看哪份资源"，还是"读哪张上游数据表"**：

- 前者：本分支资源侧对调过 → 判断跟着反
- 后者：表是上游原样搬来的 → 判断保持上游

两边都不能靠「女→男直接替换」，也不能靠 `isMale` 这类变量名。

**教训（2026-09-29）**：我先后在这一处栽了两次——
先按"玩家性别判断要反"把 (b) 类改成了 `'女'`（错，让男玩家拿到女性向技能池），
之后又写进本文档说 `'女'` 是对的（也错）。**根因是把 (a) 和 (b) 当成了同一类。**
现在 (b) 已改回 `'男'`，本文档也已更正。教训：判据要落到**被判断的那个东西的实质内容**上，
不能只看它出现在"玩家性别判断"这个语境里。

### 3.6 ⚠️ 第三类：**势力名——变量键与 CDN 文件名要分开**

三个势力名在性转时是对调性别词的，**但只对调变量键和显示文案，不动 CDN 文件名**：

| 变量键 / 显示文案（要改） | CDN 文件名（不改） |
| --- | --- |
| 男权协会（原 `女权协会`） | `莎拉斯通-女权协会事件-1.png` |
| 女性自保联盟（原 `男性自保联盟`） | — |
| 雄堕会（原 `雌堕会`） | — |

判断方法同 3.5：**这个名字是拿去查数据表／给玩家看的，还是拿去拼 URL 的**。

**权威来源是世界书**，不是代码。当前生效的世界书
`酒馆数据/角色卡/性斗学园/世界书/` 里：

| 名字 | 文件数 |
| --- | --- |
| 男权协会 | 37 |
| 女性自保联盟 | 13 |
| 雄堕会 | 18 |
| 女权协会 / 男性自保联盟 / 雌堕会 | **0** |

也就是说 **AI 收到的指令里用的是新名**。所以代码侧一旦没跟上，就会
「AI 写 `男权协会`，schema 只认 `女权协会`」——声望更新被静默丢弃，不报错。

> **注意别被旧卡副本误导**：`酒馆数据/` 下还有 `性斗学园V3.2/`、`性斗学园V3.3.2/`、
> `原版性斗学园V3.2/`、`源代码/` 等**上游旧副本**，它们里面全是旧名（`女权协会` 共 412 处）。
> 那些不是当前生效的世界书，**不要拿它们当判据**。查权威要看
> `酒馆数据/角色卡/性斗学园/世界书/`。

**2026-09-29 修正**：`变量结构/schema.ts` 的 `势力声望` 三个键此前仍是旧名
（`schema.json` 已先行改好，两边不一致），现已统一；`开局/data/npcCharacters.ts`
的 `NpcCategory` 类型、`category` 值、分节注释也一并改完。

## 四、新增角色的处理流程（硬性闸门）

上游新增角色时，**不要自作主张定男名**：

1. 我（或任何执行同步的人）先列出候选表：**上游女名 / 建议男名 / 判断依据 / 影响的资源类型**
2. **交由你逐条审核确认或改写**
3. 确认后才写入映射表

同时要检查该角色的 CDN 资源是否已存在（立绘／头像／Q版／差分），
因为男名对应的是**同一批女名文件**，不是新建资源。

## 五、已知特例

### 5.1 反向特例 4 人（保留女名显示）

`加藤鹰子`、`佐藤健子`、`田中勇子`、`李芳` —— 这 4 人**刻意保留女名**。
原因是他们性转后**仍是女性**，而其余角色性转后是男性，所以"显示用男名"的约定在他们身上正好相反。

立绘不由原 CDN 提供，而是走
[backstreetAvatarSettings.ts:21](src/性斗学园/性斗学园脚本/phone/backstreetAvatarSettings.ts#L21)
的 `NORMAL_AVATAR_URL_OVERRIDES`，指向**你自己仓库**的头像：

```text
加藤鹰子: 'https://cdn.jsdelivr.net/gh/vient-awi/myyy@main/头像/加藤鹰子.png'
```

改到这几个人时不要「顺手改成男名」。他们**各个位置该用哪个名字**是反的，别一刀切：

| 位置 | 用哪个名 | 说明 |
| --- | --- | --- |
| `ENEMY_DATABASE` / `ENEMY_SKILL_MAP` 的键 | **女名** | 数据表键 |
| `开局/npcCharacters.ts` 的 `name` / `dbKey` / `skillKey` | **女名** | 玩家看到的就是女名 |
| `PORTRAIT_NAME_MAP` / `CHIBI_RESOURCE_NAME_MAP` 的**值** | **男名** | 取 CDN 资源，原版立绘图文件名是男名 |
| `NAME_ALIASES` 的**键** | **男名** | 旧名兜底，兼容旧存档旧日志 |

> **2026-09-29 变更**：此前属性键是男名（`李强`/`佐藤健`/`田中勇`），
> 与技能键（女名）不一致 —— 那是分支性转 `enemySkillDatabase` 时的遗漏。
> 现已统一为女名，`NAME_ALIASES` 里的条目方向也随之从「女名 → 男名」翻成「男名 → 女名」。
>
> **不要**把 `PORTRAIT_NAME_MAP` 的值也"统一"掉 —— 那是 CDN 文件名，改了立绘会 404。

### 5.2 女名 → 男名 桥接 2 条（**最容易被上游改断的一条链路**）

`NAME_ALIASES` 里有两条**反向**映射：

```text
薇丝佩菈 → 维斯佩罗
黑崎晴雯 → 黑崎晴雷
```

原因是 `开局/data/npcCharacters.ts` 里这两个角色的 `dbKey` / `skillKey` 直接用了**女名**，
而 `开局/app.vue` 会拿这个 key 去裸查 `ENEMY_DATABASE` 与 `ENEMY_SKILL_MAP`——
这两张表只认男名键。所以必须靠这两条桥接连通。

> **上游任何涉及 `开局/npcCharacters.ts` 或这两个角色的改动，都要同时检查这条链路。**
> 验证方法：`薇丝佩菈`／`黑崎晴雯` 在 `enemyDatabase.ts` 中应各只出现 1 次（作为别名键），
> 其余地方应全是男名。

### 5.3 带 `_` 阶段后缀的名字

部分角色有带后缀的阶段形态，例如 `沐心岚_1`／`沐心岚_2`／`沐心岚_3`、
`克里斯_1`／`克里斯_2`。**注意后缀前面用的是男名**（不是女名），
因为这些键要在 `ENEMY_DATABASE`／`ENEMY_SKILL_MAP` 里查得到。

这些阶段键主要分布在：`战斗界面/enemySkillDatabase.ts`（最多）、
`enemyDatabase.ts`、`bossDefinitions.ts`、`constants.ts`、`开局/data/npcCharacters.ts`。
处理阶段形态时，映射与桥接逻辑同理。

### 5.4 `开局/` 目录当前**未做**性转

`开局/` 是按上游原样保留的（现实游玩中用不到，暂未改造）。
因此里面仍是女名，例如 `specialPortraitMap` 用的是女名键、
`npcCharacters.ts` 的 `name` 字段也是女名。
**这是有意保持一致的，两边都是女名所以能正常工作——不要只改一边。**

## 六、同步后的自检清单

每次同步完，按顺序跑一遍：

- [ ] **1. 构建**：`npx webpack --mode production`，要求 **0 error**
- [ ] **2. 导出警告**：`was not found` 应为 **0 条**
      （这类问题编译不报错，只在运行时炸，必须专门查）
- [ ] **3. 映射表在位**：5 张表都还在，条目数没有异常减少
- [ ] **4. 桥接完好**：`薇丝佩菈`／`黑崎晴雯` 各只出现 1 次（5.2 那两条，女名→男名）
- [ ] **5. 男名落点**：`ENEMY_DATABASE` 里存在 `维斯佩罗`、`黑崎晴雷` 等男名键
- [ ] **6. 4 人方向正确**（5.1）：`ENEMY_DATABASE`／`ENEMY_SKILL_MAP` 里是**女名**键
      （`李芳`/`佐藤健子`/`田中勇子`/`加藤鹰子`），
      而 `PORTRAIT_NAME_MAP`／`CHIBI_RESOURCE_NAME_MAP` 的**值**仍是**男名**
      （`加藤鹰子: '加藤鹰'` 这类，改了立绘会 404）
- [ ] **7. 开局校验**：跑第十节（总表）里的自查脚本，
      要求 `dbKey 落空 0`、`skillKey 落空` 只剩 `如月诗之`／`森立花`
- [ ] **8. 无女名泄漏**：改动过的文件里不应残留女名（映射表的「值」一侧、5.1 那 4 人除外）
- [ ] **9. 势力名一致**（3.6）：`变量结构/schema.ts` 的 `势力声望` 键 == `schema.json` 的键，
      且都与其他代码里的势力名一致。旧名 `女权协会`／`男性自保联盟`／`雌堕会`
      在 `src/` 下**只应出现在 CDN 文件名里**（当前仅
      `战斗界面/data/cgConfig.ts` 的 `莎拉斯通-女权协会事件-*.png` 两处）
- [ ] **10. 真机验证**（**必须人工**，自动化证明不了）：
      - 关系页／后街／CG 页的头像与立绘正常显示
      - 战斗界面角色名与台词显示为男名
      - 旧存档的角色识别不受影响
      - `开局/` 流程仍可走通（尤其走桥接的那两个角色、以及 5.1 那 4 人）

> **文件检查只证明规则写进了文件，不能证明客户端真的加载了。**
> 第 10 项必须是你亲自在酒馆里跑过才算数。
