# 性转改动对照规则

> 用途：每次同步上游 [vincentrong2005/Fatria](https://github.com/vincentrong2005/Fatria) 更新时，
> 用这份文档判断「哪些地方必须翻译、哪些可以直接照搬」，避免性转成果被上游冲掉。
>
> 本文档由 2026-09-28 的 v3.6.13 → v3.7.2 同步实践整理而成。

---

## 一、命名约定（一切规则的出发点）

| 场景 | 用哪个名字 |
| --- | --- |
| 界面显示、战斗日志、对话台词、变量键与变量值、角色昵称 | **男名** |
| CDN 资源路径（立绘／头像／Q版头像／头像差分／CG 图片文件名） | **女名** |

一句话记法：**玩家看得到的用男名，URL 里的用女名。**

**默认规则：没出现在映射表里的名字，男女两名一致**，不需要任何处理。
例如 `庄方宜`、`日向葵`、`阿娜温`、`无常`、`零`、`雪` 都属这类。

## 二、五张映射表（性转成果的核心，改上游前必查）

| 映射表 | 文件 | 条目数 | 作用 |
| --- | --- | --- | --- |
| `PORTRAIT_NAME_MAP` | [战斗界面/constants.ts](src/性斗学园/战斗界面/constants.ts) | 138 | 男名 → 立绘 CDN 女名 |
| `CHIBI_RESOURCE_NAME_MAP` | [性斗学园脚本/phone/backstreetAvatarSettings.ts](src/性斗学园/性斗学园脚本/phone/backstreetAvatarSettings.ts) | 126 | 男名 → Q版头像 CDN 女名 |
| `resourceName` 字段 | [战斗界面/data/cgConfig.ts](src/性斗学园/战斗界面/data/cgConfig.ts) | 22 处 | CG 图片的资源名 |
| `imageFolder` 字段 | [shared/avatarVariationStore.ts](src/性斗学园/shared/avatarVariationStore.ts) | 129 处 | 头像差分的文件夹名 |
| `NAME_ALIASES` | [战斗界面/enemyDatabase.ts](src/性斗学园/战斗界面/enemyDatabase.ts) | 230 | 昵称／简称 → 全名 |

**判定某条目是否属于性转改动的方法：** 看它在表里的值。
凡是「键是男名、值是女名」的条目，就是性转产物，**上游改动不能直接覆盖**。
键和值相同的自映射条目**也是有意为之**——它们用于挡住精确别名匹配那一步的前缀误伤
（例如 `雪: '雪'` 能防止「雪男」被解析到「雪」）。**不要因为「看起来冗余」就删掉。**

## 三、文案改写约定

上游新增或修改的**用户可见文本**，需要按下列约定翻译；代码注释和 `console` 日志可以不动。

### 3.1 人名

直接查上面五张表，用男名。

### 3.2 性别用词对照

| 上游（女） | 本分支（男） |
| --- | --- |
| 她／她们 | 他／他们 |
| 少女、女孩、女子 | 少年、男孩、男子 |
| 小姐、女士、夫人 | 先生、男士 |
| 姐妹 | 哥弟 |
| 娘（狼娘、猫娘…） | 郎（狼郎、猫郎…） |
| 女王、公主、女武神 | 男王、王子、男武神 |
| 母（万魔之母） | 父（万魔之父） |
| 女吊 | 男吊 |

### 3.3 必须用男名的位置（漏改会出 bug，不只是观感问题）

- **`buffName` / `statusName`** —— 这些是变量键，会参与状态匹配
- **对话日志的 template string** —— 例如 `【束缚猎物】${name}的攻击必定命中`
- **UI 文案与结算提示**
- **变量键与变量值**

## 四、新增角色的处理流程（硬性闸门）

上游新增角色时，**不要自作主张定男名**：

1. 我（或任何执行同步的人）先列出候选表：**上游女名 / 建议男名 / 判断依据 / 影响的资源类型**
2. **交由你逐条审核确认或改写**
3. 确认后才写入映射表

同时要检查该角色的 CDN 资源是否已存在（立绘／头像／Q版／差分），
因为男名对应的是**同一批女名文件**，不是新建资源。

## 五、已知特例

### 5.1 反向特例 4 人（保留女名显示）

`加藤鹰子`、`佐藤健子`、`田中勇子`、`李芳` —— 这 4 人**刻意保留女名做显示名**，
立绘不由原 CDN 提供，而是走
[backstreetAvatarSettings.ts:21](src/性斗学园/性斗学园脚本/phone/backstreetAvatarSettings.ts#L21)
的 `NORMAL_AVATAR_URL_OVERRIDES`，指向**你自己仓库**的头像：

```text
加藤鹰子: 'https://cdn.jsdelivr.net/gh/vient-awi/myyy@main/头像/加藤鹰子.png'
```

改到这几个人时不要「顺手改成男名」；也不要以为它们该有原版立绘——
它们本来就是外部链接，因此这 4 人在映射表里**没有女名对照项**。

### 5.2 女名 → 男名 桥接 2 条（**最容易被上游改断的一条链路**）

`NAME_ALIASES` 里有两条**反向**映射：

```text
薇丝佩菈 → 维斯佩罗
黑崎晴雯 → 黑崎晴雷
```

原因是 `开局/data/npcCharacters.ts` 里这两个角色的 `dbKey` / `skillKey` 直接用了**女名**，
而 `开局/app.vue` 会拿这个 key 去裸查 `ENEMY_DATABASE` 与 `ENEMY_SKILL_MAP`——
这两张表只认男名键。所以必须靠这两条桥接连通。

> **上游任何涉及 `开局/npcCharacters.ts` 或这两个角色的改动，都要同时检查这条链路。**
> 验证方法：`薇丝佩菈`／`黑崎晴雯` 在 `enemyDatabase.ts` 中应各只出现 1 次（作为别名键），
> 其余地方应全是男名。

### 5.3 带 `_` 阶段后缀的名字

部分角色有带后缀的阶段形态，例如 `沐心岚_1`／`沐心岚_2`／`沐心岚_3`、
`克里斯_1`／`克里斯_2`。**注意后缀前面用的是男名**（不是女名），
因为这些键要在 `ENEMY_DATABASE`／`ENEMY_SKILL_MAP` 里查得到。

这些阶段键主要分布在：`战斗界面/enemySkillDatabase.ts`（最多）、
`enemyDatabase.ts`、`bossDefinitions.ts`、`constants.ts`、`开局/data/npcCharacters.ts`。
处理阶段形态时，映射与桥接逻辑同理。

### 5.4 `开局/` 目录当前**未做**性转

`开局/` 是按上游原样保留的（现实游玩中用不到，暂未改造）。
因此里面仍是女名，例如 `specialPortraitMap` 用的是女名键、
`npcCharacters.ts` 的 `name` 字段也是女名。
**这是有意保持一致的，两边都是女名所以能正常工作——不要只改一边。**

## 六、同步后的自检清单

每次同步完，按顺序跑一遍：

- [ ] **1. 构建**：`npx webpack --mode production`，要求 **0 error**
- [ ] **2. 导出警告**：`was not found` 应为 **0 条**
      （这类问题编译不报错，只在运行时炸，必须专门查）
- [ ] **3. 映射表在位**：5 张表都还在，条目数没有异常减少
- [ ] **4. 桥接完好**：`薇丝佩菈`／`黑崎晴雯` 各只出现 1 次
- [ ] **5. 男名落点**：`ENEMY_DATABASE` 里存在 `维斯佩罗`、`黑崎晴雷` 等男名键
- [ ] **6. 无女名泄漏**：改动过的文件里不应残留女名（映射表的「值」一侧除外）
- [ ] **7. 真机验证**（**必须人工**，自动化证明不了）：
      - 关系页／后街／CG 页的头像与立绘正常显示
      - 战斗界面角色名与台词显示为男名
      - 旧存档的角色识别不受影响
      - `开局/` 流程仍可走通（尤其走桥接的那两个角色）

> **文件检查只证明规则写进了文件，不能证明客户端真的加载了。**
> 第 7 项必须是你亲自在酒馆里跑过才算数。

## 八、自动更新链路（**已改为只检测、不拉取**）

本分支有两处原本会自动从**上游仓库**拉取内容，会把性转版替换成原版。
**现已全部改为「只检测、不拉取」**：

| 位置 | 原行为 | 现行为 |
| --- | --- | --- |
| [性斗学园脚本/scriptUpdater.ts](src/性斗学园/性斗学园脚本/scriptUpdater.ts) | 按发布标签拉取上游 `dist/…/index.js` 并改写脚本 URL | `applyScriptUpdate()` 一律拒绝执行，只回报上游版本 |
| [自动更新世界书脚本/index.ts](src/性斗学园/自动更新世界书脚本/index.ts) | `importRawCharacter` 拉取上游 `.png` 覆盖角色卡 | 只比对版本号并提示，不再拉取 |

**改这两处时注意**：检测能力（版本比对、状态显示、提示）要保持可用，
只保留「不写入／不覆盖」这一条底线即可。

**当前状态：已处置（2026-09-28）—— 两条链路均改为「只检测、不拉取」，
上游有新版本时只提示、不覆盖。详见 [自动更新链路风险说明.md](自动更新链路风险说明.md) 第七节。**

> 另注：`scriptUpdater.ts` 的 `SCRIPT_VERSION` 已随本次同步改为 `3.7.2`。
> 即使上游发布 v3.7.3，也只会**提示**版本落后，不会覆盖你的性转版。
